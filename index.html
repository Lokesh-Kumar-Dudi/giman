Quick Setup

Initialize with a single command. No complex config files to edit manually.

gid init

Context Aware

Automatically switches SSH keys based on the directory you are working in.

Full Control

Manage identities, list status, and apply changes instantly from the terminal.

gid status gid identity list

How it works

GiMan manages three system files on your behalf — all changes are reversible and opt-in.

~/.giman/config.json

Source of truth. Stores identities, SSH key paths, and directory mappings. Edit manually or use gid identity commands.

~/.gitconfig

GiMan appends includeIf "gitdir:..." blocks that activate per-identity gitconfigs for specific directories automatically.

~/.ssh/config

GiMan writes Host alias blocks (e.g. github-personal) that map to github.com with your specific SSH key.

Complete quick-start walkthrough
# 1. Install
$ npm install -g giman
# 2. Set up first identity (interactive)
$ gid init
→ Enter ID (e.g. "personal"), name, email, SSH host alias (e.g. "github-personal")
→ Generate or select an existing SSH key
# 3. Add a second identity
$ gid identity add
→ Repeat for "work" identity
# 4. Map directories
$ gid dir add ~/dev/personal --identity personal
$ gid dir add ~/dev/work --identity work
# 5. Check it works
$ cd ~/dev/work/my-project
$ gid status
✓ Identity: work — Jane Work <jane@company.com>
# 6. Clone using the right identity
$ gid clone git@github.com:company/project.git
→ Prompts to pick identity, then clones with rewritten URL
# 7. Commits use the right identity automatically
$ git commit -m "feat: add feature"
Committed as: Jane Work <jane@company.com>

Commands

All commands are prefixed with gid.

gid init

Interactive first-time setup. Detects existing config and offers to re-apply it. Run once per machine.

gid status

Show which identity is active for the current directory. No arguments needed.

gid apply

Sync config to system files: rewrites ~/.ssh/config and ~/.gitconfig. Run after manual config edits.

gid clone <url> [dir]

Clone a repo via SSH. Prompts to select an identity and rewrites the URL to use that identity's host alias.

gid identity list

List all identities with their SSH key, host alias, and mapped directories.

gid identity add

Add a new identity interactively (ID, name, email, SSH key, host alias).

gid identity edit <id>

Edit name, email, or SSH host alias for an identity. Run gid apply afterwards to sync SSH config.

gid identity remove <id>

Remove an identity, its SSH Host block, and all its gitconfig includeIf entries from ~/.gitconfig.

gid identity show <id>

Show all details for one identity including mapped directories.

gid dir add <path> -i <id>

Map a directory to an identity. Any repo inside that path uses the identity's user and SSH key automatically.

gid dir remove <path>

Remove a directory mapping. Git will stop auto-selecting the identity for that folder.

gid dir list

List all directory-to-identity mappings.

Sandbox testing

Try GiMan without touching your real SSH or git config by running it in an isolated home directory.

Isolated sandbox — safe to run anywhere 
# Create an isolated sandbox home
export GIMAN_HOME="$(mktemp -d)/giman-sandbox"
mkdir -p "$GIMAN_HOME/.ssh" "$GIMAN_HOME/.giman" "$GIMAN_HOME/dev/personal" "$GIMAN_HOME/dev/work"

# Install giman globally
npm install -g giman

# Generate SSH keys for two identities
ssh-keygen -t ed25519 -f "$GIMAN_HOME/.ssh/giman_personal" -N '' -C 'giman-personal'
ssh-keygen -t ed25519 -f "$GIMAN_HOME/.ssh/giman_work"     -N '' -C 'giman-work'

# Write a pre-built config (skip interactive prompts)
cat > "$GIMAN_HOME/.giman/config.json" << EOF
{
  "identities": [
    {
      "id": "personal", "name": "Jane Dev", "email": "jane@personal.dev",
      "sshKeyPath": "$GIMAN_HOME/.ssh/giman_personal",
      "sshHost": "github-personal", "directories": ["$GIMAN_HOME/dev/personal"]
    },
    {
      "id": "work", "name": "Jane Work", "email": "jane@company.com",
      "sshKeyPath": "$GIMAN_HOME/.ssh/giman_work",
      "sshHost": "github-work", "directories": ["$GIMAN_HOME/dev/work"]
    }
  ],
  "defaultIdentity": "personal"
}
EOF

# Point HOME at the sandbox so giman reads/writes there
HOME="$GIMAN_HOME"

# Apply — writes SSH config and .gitconfig
echo "y" | HOME="$GIMAN_HOME" gid apply

# --- Test identity list ---
HOME="$GIMAN_HOME" gid identity list

# --- Test status in a mapped dir ---
cd "$GIMAN_HOME/dev/work"
HOME="$GIMAN_HOME" gid status
# Expected: ✓ Identity: work — Jane Work

# --- Test that git picks up identity gitconfig ---
cd "$GIMAN_HOME/dev/work"
git init my-repo && cd my-repo
git config --list --show-origin | grep "user\."
# Expected: jane@company.com from work.gitconfig

# --- Test commit ---
echo "hello" > README.md
git add README.md
git commit -m "Initial commit"
git log --format="%an <%ae>" HEAD
# Expected: Jane Work <jane@company.com>

# --- Test relative path dir add ---
cd "$GIMAN_HOME/dev/personal"
HOME="$GIMAN_HOME" gid dir add . --identity personal
# Expected: stores absolute path /...giman-sandbox/home/dev/personal
HOME="$GIMAN_HOME" gid dir list

# --- Test identity remove cleans up gitconfig ---
HOME="$GIMAN_HOME" gid identity remove work
cat "$GIMAN_HOME/.gitconfig"
# Expected: only the personal includeIf remains

# Inspect what was written
cat "$GIMAN_HOME/.ssh/config"
cat "$GIMAN_HOME/.gitconfig"
echo "Sandbox at: $GIMAN_HOME"

The sandbox uses a temporary directory as HOME so none of your real config files are touched. Delete the temp directory when done.

Changelog

What changed in each release.

v1.0.4 2026-07-28 bugfix
fix

gid identity remove now cleans up ~/.gitconfig includeIf entries

Removing an identity previously left stale [includeIf] blocks pointing at deleted gitconfig files. These are now pruned on removal.

fix

SSH host alias now requires valid hostname characters only

Spaces and special characters are now rejected at input. Previously, entering github my work would write a broken Host github my work entry — three patterns instead of one.

fix

SSH keygen: disconnected inherited stdin and unread stdout pipe

The ssh-keygen subprocess previously inherited the parent's terminal stdin and had stdout piped but never consumed. Changed to ['ignore', 'ignore', 'pipe'] — only stderr is captured for error reporting.

fix

resolveHome('$HOME') now correctly expands to the home directory

Bare $HOME (without trailing slash) was returned as the literal string. It is now expanded the same way as $HOME/ and ~/.

fix

gid dir add now resolves relative paths against CWD

Paths like ./subdir, ., and ../other are now expanded to absolute paths before being stored. Previously they were saved as-is, causing gid status to never match since the relative path was resolved against whichever directory you happened to run the next command from.

chore

Merged duplicate import in status.ts

Two separate import statements from ../services/config.js were consolidated into one.

v1.0.3 2025-10-12 feature
feat

Added gid clone command

Clone a GitHub repo via SSH with interactive identity selection. GiMan rewrites the URL to use the chosen identity's host alias automatically.

feat

Path traversal guard on SSH key and gitconfig paths

Identity IDs are validated against /^[a-zA-Z0-9_-]+$/ and paths are asserted to stay within their expected base directories.

v1.0.0 2025-08-01 initial release
feat

Core identity management: gid init, gid identity add/edit/remove/show/list

Create and manage multiple git identities (name, email, SSH key, host alias) stored in ~/.giman/config.json.

feat

Directory mappings via gid dir add/remove/list

Map a directory to an identity so git automatically uses the right user and SSH key for any repo inside that path.

feat

SSH config and gitconfig sync via gid apply

Writes Host blocks to ~/.ssh/config and includeIf rules to ~/.gitconfig. All changes are opt-in and GiMan markers make them safe to re-run.
